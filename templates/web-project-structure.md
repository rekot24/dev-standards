# Web project folder structure — Next.js + TypeScript + Supabase

Copy this layout when starting a new web project. Delete what doesn't apply — but think before you delete.
(Approved variant: React + Vite SPA — swap `app/` for `src/main.tsx` + a router and record it under Known deviations.)

```
project-name/
  package.json  tsconfig.json  next.config.ts  eslint.config.mjs  vitest.config.ts
  .gitignore
  .env.local               ← real values; NEVER committed
  .env.example             ← every variable name, empty values; committed
  README.md                ← what this is, how to run it, required env vars
  CLAUDE.md                ← from templates/CLAUDE-web.md
  ROADMAP.md  SPEC.md      ← from templates/
  .github/workflows/ci.yml ← from templates/ci/web-ci.yml

  src/
    app/                   ← routes. Keep thin: compose features, don't implement them.
      layout.tsx  page.tsx  loading.tsx  error.tsx  global-error.tsx
      api/                 ← route handlers (webhooks, server-only work)
    features/<feature>/    ← one folder per feature
      components/          ← UI for this feature
      hooks.ts             ← TanStack Query hooks (what components call)
      api.ts               ← the ONLY file that talks to Supabase for this feature
      schemas.ts           ← zod schemas + inferred types
    components/shared/     ← Button, Input, Modal, LoadingState, ErrorState, EmptyState
    context/               ← AuthContext, SettingsContext, QueryProvider
    constants/             ← index.ts, flags.ts, plans.ts, statuses.ts   (snippets/constants.ts)
    lib/
      env.ts               ← zod-validated env           (snippets/env.ts)
      supabase/client.ts   ← browser client              (snippets/supabase-client.ts)
      supabase/server.ts   ← server client (cookie-based session)
      logger.ts            ← debug + persistent logging  (snippets/logger.ts)
      money.ts             ← integer-cent helpers        (snippets/money.ts)
      formatters.ts  validators.ts   ← pure functions only
    hooks/useFeatureFlags.ts         (snippets/useFeatureFlags.ts)
    styles/globals.css     ← all design tokens + base styles (see web-frontend-design.md)
    types/database.ts      ← GENERATED by `supabase gen types typescript` — never hand-edit

  supabase/
    migrations/            ← the schema, one file per change, in order (never edit a shipped one)
    seed.sql               ← fake data to rebuild a dev database

  tests/
    unit/                  ← Vitest: pure logic (money, state machines, mappers)
    rls/                   ← row-level-security isolation tests
    e2e/                   ← Playwright: 1–3 critical flows

  docs/
    decisions.md           ← architectural decisions with dates and reasons
```

## Environment variables

Document every variable in `.env.example` and the README. Never commit real values.

```
# Public — shipped to every visitor's browser (NEXT_PUBLIC_ prefix). Publishable values only.
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=

# Server-only — NEVER use a NEXT_PUBLIC_ prefix on anything below
SUPABASE_SERVICE_ROLE_KEY=
# STRIPE_SECRET_KEY=            (add when payments are integrated)
# STRIPE_WEBHOOK_SECRET=
# TWILIO_AUTH_TOKEN=            (add when SMS is integrated)
# SENTRY_DSN=                   (add with monitoring)
```
> **The prefix rule:** if a value starts with `NEXT_PUBLIC_` (or `VITE_` in a Vite app), the browser can read it.
> A secret with that prefix is a leaked secret.

## package.json scripts (the names CI expects)

```json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "lint": "eslint .",
    "typecheck": "tsc --noEmit",
    "test": "vitest run",
    "gen:types": "supabase gen types typescript --project-id <id> > src/types/database.ts"
  }
}
```
Turn on `"strict": true` in `tsconfig.json`, and add the ESLint `no-console` rule (the logger is the only exception).

## Provider wiring pattern (root layout)

Order matters: the query client first, then auth, then settings (settings need the tenant id from auth).

```tsx
// src/app/providers.tsx
'use client'
import { useState, type ReactNode } from 'react'
import { QueryClient, QueryClientProvider } from '@tanstack/react-query'
import { AuthProvider } from '@/context/AuthContext'
import { SettingsGate } from '@/context/SettingsGate'   // renders SettingsProvider once a tenant id exists

export function Providers({ children }: { children: ReactNode }) {
  const [client] = useState(() => new QueryClient())   // one per browser session; never at module level
  return (
    <QueryClientProvider client={client}>
      <AuthProvider>
        <SettingsGate>{children}</SettingsGate>
      </AuthProvider>
    </QueryClientProvider>
  )
}
```
