# Standard project folder structure — Python

Copy this layout when starting a new Python project.
Delete folders that don't apply — but think before you delete.

```
project-name/
  main.py                   ← entry point only; wires everything together
  pyproject.toml            ← dependencies, Python version, ruff/pytest config (see below)
  uv.lock                   ← exact dependency versions (generated by uv; commit it)
  .pre-commit-config.yaml   ← checks that run before every commit (see below)
  .env.example              ← names of required environment variables, no values (committed)
  README.md                 ← what this app does, how to run it, what each folder is
  CLAUDE.md                 ← Claude session context (copy from templates/CLAUDE.md)
  ROADMAP.md  SPEC.md       ← the path / the current step (copy from templates/)
  .gitignore
  .github/workflows/ci.yml  ← copy from templates/ci/python-ci.yml

  config/
    settings.json           ← persisted values (gitignored if sensitive or machine-specific)
    settings_schema.py      ← field definitions, types, and defaults
    settings_store.py       ← the live settings object (copy from snippets/settings_store.py)
    constants.py            ← all named values, grouped and commented

  core/                     ← main logic: workers, managers, orchestration
  detection/                ← input reading, pattern matching, sensors
  actions/                  ← things the app does (clicks, API calls, writes)
  ui/                       ← display only; never writes to workers directly
  tools/                    ← reusable utilities; general enough to copy to other projects
                               (logger.py from snippets/logger.py lives here)
  assets/  profiles/

  tests/
    conftest.py             ← shared fixtures: fake backends, sample data
    test_*.py               ← one file per module under test

  docs/
    decisions.md            ← architectural decisions with dates and reasons

  logs/   .gitkeep          ← keeps the folder in git without committing log files
  debug/  .gitkeep          ← screenshots and debug output land here
```

## pyproject.toml — starter

```toml
[project]
name = "project-name"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = [
  # runtime dependencies here
]

[dependency-groups]
dev = ["pytest", "ruff", "pre-commit"]      # add "pyright" when type hints are in place

[tool.ruff]
line-length = 100
target-version = "py312"

[tool.ruff.lint]
# E/F = core errors, I = import order, B = likely bugs, UP = modern syntax,
# T20 = no stray print(), E722 (in E) = no bare except
select = ["E", "F", "I", "B", "UP", "T20"]

[tool.pytest.ini_options]
testpaths = ["tests"]
```

## .pre-commit-config.yaml — starter

```yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.8.0            # update with `pre-commit autoupdate`
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format
```
Activate once per clone: `pre-commit install`.

## Everyday commands (run in the project folder)

| Command | What it does |
|---|---|
| `uv sync` | Create/refresh the virtual environment from `pyproject.toml` + lockfile |
| `uv run python main.py` | Run the app inside that environment |
| `uv run ruff check .` | Lint (add `--fix` to auto-fix) |
| `uv run pytest` | Run tests |

## .gitignore minimums

```

__pycache__/
.venv/
.env
config/settings.json        # if it contains secrets or machine-specific paths
logs/
debug/

```
